# AI質問機能 要件定義書（`requirements.md`）レビュー結果

要望書（`docs/ai/request.md`）と作成した要件定義書（`docs/ai/requirements.md`）を照合した結果、検出された不整合、曖昧さ、不足項目の一覧および修正案は以下の通りです。

---

## 指摘・改善事項一覧

### 1. 【要望の未対応】エラー発生時のログ出力およびグローバルエラーハンドラー連携
* **対象ID**: `REQ-AI-F004`
* **問題点**: 要望書（3.1.3）では「グローバルエラーハンドラーへの連携を行う」と記載されていますが、現在の受入条件が「Expressサーバーがクラッシュせずログが記録されること」となっており、既存のグローバルエラーハンドラー（ミドルウェア等）へエラーを渡す（`next(err)` 等）という実装方針・検証視点が漏れています。
* **修正案**: 受入条件に「非同期処理内の例外捕獲時に `next(error)` 等を通じてグローバルエラーハンドラーへエラーが伝播されること」を明記します。

### 2. 【不要な追加（要件の逸脱）】公開条件 / 公開停止条件における「非活性化」の記述
* **対象ID**: 条件定義「6. 公開条件 / 公開停止条件」
* **問題点**: 「`AI_API_KEY` 未設定時に機能を非活性化（または安全なエラー画面・メッセージを返却）とし、機能単位で公開停止状態とする」という記述があります。フロントエンド側でAPIキーの有無を検知してボタン等を非活性化（disabled）する仕様は要望書に存在せず、サーバーサイドの環境変数管理の観点からも不要な複雑化を招きます。
* **修正案**: 条件を簡素化し、「APIキー未設定時はバックエンド側で安全なエラー（500/503等）を返し、画面には一律でシステムエラーメッセージを表示する」という動作に統一します。

### 3. 【曖昧な受入条件】REQ-AI-N003（既存機能非破壊）の検証範囲
* **対象ID**: `REQ-AI-N003`
* **問題点**: 受入条件が「既存のTODO機能（CRUD）が正常に動作すること」となっていますが、要望書（3.2.3 / 4.1）にある「404ハンドリング」「ルーティング統合（`index.ts` への `app.use('/ai', ...)` 追加）」「DB接続」への影響がないことの検証方法が曖昧です。
* **修正案**: 受入条件を「`index.ts` へのルーター追加後も、既存のTODO機能（CRUD）、既存DB接続、および未定義ルートに対する404ハンドリングが影響を受けずに正常動作すること」に具体化します。

### 4. 【曖昧な受入条件】REQ-AI-F001・F002（画面・応答表示）の具体性
* **対象ID**: `REQ-AI-F001`, `REQ-AI-F002`
* **問題点**: 受入条件が「領域が存在すること」「正しく表示されること」と抽象的であり、通信中の状態（ローディング表示）や送信ボタンの連続押下防止などの基本的なUI振る舞いがテスト条件に含まれていません。
* **修正案**: 受入条件に「リクエスト処理中に重複送信を防止（ボタン無効化等）すること」「取得した応答テキストが画面の指定領域に表示されること」を追加・明確化します。

### 5. 【矛盾・未定義】非機能要件におけるセキュリティ要件の対応漏れ
* **対象ID**: `WISH-AI-004` / `REQ-AI-N002`
* **問題点**: 対応表（4章）では `WISH-AI-004` に対し `REQ-AI-N002` のみをマッピングしていますが、要望書（3.2.2）の「APIキー等の機密情報はソースコードに直書きしない」点について、受入条件に `.gitignore` 等への `.env` 設定ファイルの除外チェックなど、リポジトリ管理上の検証視点が欠けています。
* **修正案**: `REQ-AI-N002` の受入条件に「`.env` ファイルがバージョン管理（`.gitignore`）から除外されており、コード上に平文の鍵が含まれないこと」を追加します。
