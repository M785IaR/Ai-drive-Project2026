# AI質問機能 テスト仕様・結果記録表 (`docs/ai/test-results.md`)

本ドキュメントは、要件定義書（`docs/ai/requirements.md`）、設計書（`docs/ai/spec.md`）、および現在の実装に基づくテスト項目と実行結果を記録するためのテスト表です。

* **運用ルール**:
  * テスト実施前は「実測結果」を空欄、「判定」を `未実施` のままとし、未実行のテストを合格としないこと。
  * 外部の Gemini API への大量リクエストを避けるため、異常系および境界値の多くは「ローカル模擬手法（開発者ツールでのリクエスト改変・応答モック・環境変数の一時切り替え等）」を用いて確認すること。

## 3. 外部APIを大量に呼ばずに異常系を確認するローカル模擬手順

Gemini API の無料枠・トークン消費や課金を抑えつつ異常系を確実に検証するため、以下のローカル模擬手法を使用します。

1. **デモ停止制御の確認（T15 / AT-AI-04）**:
   * `.env` の `AI_DEMO_ENABLED=false` に変更してサーバーを再起動する（Gemini API への外部通信は一切発生しません）。
2. **不正モデル・設定不備による `502` 変換の確認（T16）**:
   * `.env` の `GEMINI_API_KEY` を一時的に空にする、または存在しないモデル名（例: `GEMINI_MODEL=invalid-model-test`）にして1回だけ送信し、SDKエラーが安全な `502` へ変換されることを確認する。
3. **不正JSON / HTML応答・通信エラー・45秒タイムアウトのブラウザ模擬（T17 / T18 / AT-AI-10）**:
   * 外部APIを呼ばずにブラウザの「開発者ツール（DevTools）」で以下を実施する。
     * **オフライン模擬**: Network タブのプリセットを `Offline` に切り替えて送信し、通信エラー時の入力保持とUI復帰を確認する。
     * **応答モック / 遅延**: DevTools の「ローカルオーバーライド（Local Overrides）」または Request blocking を使用し、`/api/ai/ask` に対して不正な HTML 文字列の返却や 45 秒以上の遅延を発生させてタイムアウト表示と `finally` 解除を確認する。
4. **SQLインジェクション・XSS のローカル確認（T19 / AT-AI-09）**:
   * `AI_DEMO_ENABLED=true` で `<script>alert('XSS')</script>` や `'; DROP TABLE ai_qa_logs; --` を1回送信するか、テスト用DBに該当文字列を1件 `INSERT` して画面表示とテーブル保全を確認する。
