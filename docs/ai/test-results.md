## 3. 外部APIを大量に呼ばずに異常系を確認するローカル模擬方法

Gemini API の無料枠・課金枠を消費せず、安全かつ確実に異常系（T16〜T20、AT-AI-02〜04）を確認する手順は以下のとおりです。

1. **デモ停止制御の確認（T16, T17, AT-AI-02）**:
   * `.env` の `AI_DEMO_ENABLED=false` に変更してサーバーを再起動します（外部APIは一切呼ばれません）。
2. **認証・設定不備による `502` エラー確認（T18）**:
   * `.env` の `GEMINI_MODEL=invalid-model-name`（存在しないモデル名）または `GEMINI_API_KEY=`（空欄）にして質問を送信します。空欄の場合は外部通信前にサーバー側ガードで即座に `502` を確認できます。
3. **空回答（`AI_EMPTY_RESPONSE`）の模擬確認（T19）**:
   * 検証時のみ一時的に `src/apps/ai/aiService.ts` の `generateAnswer` 戻り値を `return '   ';` に書き換えて動作確認し、確認後に元へ戻します。
4. **ブラウザ側タイムアウト（45秒）および不正HTML応答の確認（T20, AT-AI-04）**:
   * **ブラウザタイムアウト**: 検証時のみ `public/ai/app.js` の `ASK_TIMEOUT_MS` を `100`（0.1秒）に変更して送信すると、API完了前にブラウザ側 `AbortController` が発火し、タイムアウト案内と `finally` によるUI復帰を即座に確認できます（確認後に `45_000` へ戻します）。
   * **HTML / 不正JSON応答**: ブラウザ開発者ツール（DevTools）の Network タブで `/api/ai/ask` を右クリック →「Override content（コンテンツをオーバーライド）」から `<html>502 Bad Gateway</html>` に書き換えて再送信すると、実サーバーや外部APIを叩かずにパース失敗時のUI復帰（T20）を確認できます。
